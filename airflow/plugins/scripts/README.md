# gtfs-rt-parser

This script parses GTFS RT protobufs into newline-delimited JSON for querying
via BigQuery external tables. This script aggregates data hourly, so we can fit
within BigQuery external table file count limits.


## Running automated tests

1. Install uv dependencies for airflow:

```bash
$ uv sync
```

2. Run gtfs-rt-parser tests:

```bash
$ uv run pytest tests/scripts/test_gtfs_rt_parser.py
```

To run only a specific test, you can reference like this:

```bash
$ uv run pytest tests/scripts/test_gtfs_rt_parser.py::TestGtfsRtParser::test_no_vehicle_positions_for_date
```


## GTFS-RT Validator JAR file

The `gtfs-realtime-validator-lib-x.y.z-yyyymmdd.HHMMss-v.jar` is an old snapshot
of the GTFS Realtime validator that now lives under
[MobilityData](https://github.com/MobilityData/gtfs-realtime-validator).
We've vendored an old version to help make our builds less dependent on external
services. We should begin using the officially-published
[packages](https://github.com/orgs/MobilityData/packages?repo_name=gtfs-realtime-validator)
at some point in the future.

## GTFS-RT compactor regression tests

From `airflow/`, run the unit tests and the recorded CLI integration test:

```bash
uv run pytest tests/scripts/test_gtfs_rt_compactor*.py
```

No special flags: the shared `tests/conftest.py` already provides a throwaway
`AIRFLOW_HOME`, puts `plugins/` on the path, and carries the VCR/urllib3
replay shims the recorded test depends on. The regular CI pytest run also
discovers both files automatically.

The VCR test uses real Google Cloud Storage and gcsfs clients, real PyArrow,
and the Typer entrypoint. Three synthetic objects produce two Parquet row
groups; the other 23 hours are empty. It checks the staged upload, copy to the
final path, temporary-object cleanup, outcome JSONL and metadata, and daily
manifest. Observers inspect the bytes generated by the current run while
allowing the real writers to execute: replaying a recorded output download
alone would not detect a serialization regression. Playback uses anonymous
credentials and requires no Google login for this test.

To deliberately record a new cassette:

1. Refresh your staging Application Default Credentials.
2. Choose an unused synthetic date in `test_gtfs_rt_compactor_vcr.py` (`DT`).
   The test refuses existing input/output partitions and creates source objects
   with a generation precondition. It uses only `calitp-staging-pytest` and
   `calitp-staging-pytest-parsed`; never substitute production buckets.
3. Run:

   ```bash
   uv run pytest tests/scripts/test_gtfs_rt_compactor_vcr.py --record-mode=rewrite
   ```

4. Review the cassette under `tests/scripts/cassettes/test_gtfs_rt_compactor_vcr/`
   and run again without `--record-mode` before committing it. Authorization
   headers and resumable-upload session IDs are filtered. Authentication
   endpoints are excluded from recording.

Recording leaves the tiny synthetic source and final output fixtures in the
test buckets for their normal lifecycle cleanup. Only the compactor's own
temporary upload is deleted. Dependency-update PRs replay the committed
cassette; investigate failures before deciding whether a new recording is needed.
